# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-18
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Labyrinthe 3D is a port of the user's existing Expo SDK 53 app (the original Maze project's `mobile/` app (local, not published)), which already renders a
first-person 3D maze with **Three.js on an `expo-gl` WebGL context** (the "fake canvas" set-up of expo-three, without
the expo-three package). The PRD needs:

- Rendering: real-time 3D at a steady 60 fps (walls, pillars, fog, point lights, footprint decals, wall plaques), a
  2D plan (SVG) and React Native overlays (HUD, arrows, menus).
- Audio: pre-rendered sound files (drone loop, footsteps, whoosh, click, chime, chord, creak), mute toggle.
- Haptics: light impact and success notification.
- Storage: score history and settings (AsyncStorage).
- Keep awake during a game, immersive fullscreen landscape, a debug-only deep link (D4).
- Firebase Analytics + Crashlytics, opt-in.
- Local build on Windows, sideloaded arm64 APK, no cloud build.

Library check against Expo SDK 57 (React Native 0.86, New Architecture mandatory):

| Need | Library | Expo prebuild / New Arch |
|---|---|---|
| 3D rendering | `expo-gl` 57.x + `three` (pure JS, 0.18x) | Expo module, published for SDK 57; three needs no native code |
| 2D plan | `react-native-svg` | autolinking, New Arch supported, used by the source |
| Audio | `expo-audio` | Expo module (expo-av removed in SDK 55) |
| Haptics | `expo-haptics` | Expo module |
| Keep awake | `expo-keep-awake` | Expo module |
| Immersive fullscreen | `expo-navigation-bar` / `expo-status-bar` (or `react-native-edge-to-edge` as in the source) | Expo modules / config plugin |
| Deep link (debug) | `expo-linking` + `scheme` in app config | built in |
| Storage | `@react-native-async-storage/async-storage` | autolinking |
| Telemetry | `@react-native-firebase/app`, `/analytics`, `/crashlytics` v26 | config plugins |

No custom native module and no hand-edited Android code are needed.

Rendering approach: **Three.js on expo-gl**, driven by a game loop outside React (`requestAnimationFrame` +
`gl.endFrameEXP()`), as in the source. No Reanimated or Skia: the 3D view is a single GLView and the overlays are
plain Views that only re-render on game-state changes (not per frame).

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | expo-gl, audio, haptics are Expo modules; bare would need `install-expo-modules` |
| Need to hand-edit native Android code continuously | high | no | no | |
| Custom native module (Kotlin/C++) needed | medium | no | no | |
| Upgrade effort over time | medium | low (bump SDK, `expo install --fix`) | higher (Upgrade Helper merges) | |
| Build simplicity on this machine (local Gradle) | medium | proven by the 3 published factory games | works, not used yet in the factory | |
| Firebase setup effort | low | config plugins | manual Gradle setup | |
| Continuity with the source app | medium | same stack (Expo + expo-gl + three) | rewrite of the native set-up | |

## Decision

**Expo (CNG, local prebuild), SDK 57, with Three.js on expo-gl.** Reasons:

1. The source game already runs on Expo + expo-gl + three: the port keeps a proven rendering path; only the SDK moves
   from 53 to 57.
2. Every library the PRD needs is an Expo module or autolinks with prebuild; nothing forces bare.
3. It is the factory's proven path (3 games built, verified and released locally on this machine).

## Consequences

- `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through `app.config.js` and
  config plugins (landscape, immersive mode, scheme, AD_ID removal, Firebase).
- The SDK 53 → 57 move must be checked early (scaffold phase): expo-gl and three render on the New Architecture,
  with a smoke test on the emulator and the phone. Risk: if expo-gl showed a blocking regression on SDK 57, it is
  raised to the user before building more (no silent switch of renderer).
- The source JS modules (`shared/core`, `shared/three`) are converted to TypeScript inside the app; three types come
  from `@types/three`.
- Jest cannot run WebGL: the engine and walker are pure TS and tested in Node; rendering is proven by Maestro
  screenshots and device frame stats (AC-30).
- Bare: not chosen; `android/` would be committed and upgrades would follow the React Native Upgrade Helper.

## Alternatives considered

- **Bare React Native**: no criterion requires it; more upgrade work and manual Firebase setup, for no gain.
- **Skia (2.5D raycasting) instead of WebGL**: would mean rewriting the renderer and losing the source's 3D look;
  rejected.
- **react-native-wgpu + Three.js WebGPU**: newer and heavier, no need given expo-gl works; rejected.
